# Kairoseth Agent Bridge — ES/EN Contract / Contrato ES/EN

## ES — Regla de producto

Kairoseth Agent Bridge es bilingüe **español + inglés** en todas las superficies visibles para personas, agentes y sistemas que consuman metadatos descriptivos.

La localización no debe duplicar el runtime ni alterar identificadores técnicos.

### Qué se localiza

Debe existir soporte ES/EN para:

- títulos y descripciones de tools;
- textos de discovery expuestos por MCP y futuros protocolos;
- mensajes seguros devueltos a clientes cuando una operación requiere aprobación, es denegada o falla;
- textos visibles en futuras interfaces, instaladores y superficies de Kairoseth Platform;
- documentación orientada a uso/operación cuando sea relevante para cliente o administrador.

### Qué NO se localiza

Permanecen estables e independientes del idioma:

- tool IDs y namespaces;
- connector IDs e instance IDs;
- nombres de campos de protocolo;
- códigos de error (`KAIROSETH_APPROVAL_REQUIRED`, etc.);
- JSON schemas y claves de payload salvo que una integración externa exija otra cosa;
- correlation IDs, event IDs, nonces y fingerprints;
- contratos de seguridad y decisiones READ / WRITE / CRITICAL.

Ejemplo:

```text
generic-rest.crm.customers.get     ← ID estable
ES: Obtener cliente                ← título localizado
EN: Get customer                   ← título localizado
```

## Contrato de código

El core define únicamente los locales soportados:

```text
es
en
```

`ToolDefinition.localizations` puede declarar ambos textos. El Connector SDK preserva esas traducciones al registrar la tool en `ToolRegistry`, por lo que MCP, A2A y futuros adaptadores pueden reutilizar la misma fuente.

Si una traducción no existe, se utiliza `name` / `description` canónico como fallback. El fallback evita romper conectores antiguos, pero los conectores oficiales de Kairoseth deben publicar ES y EN.

## Selección de idioma

### MCP HTTP

`Accept-Language` puede seleccionar `es` o `en` para discovery y mensajes seguros. Variantes regionales como `es-ES`, `es-MX`, `en-US` o `en-GB` se normalizan al idioma base soportado.

### MCP stdio / runtime local

La instalación define `defaultLocale` (`es` o `en`).

### InvocationContext

`metadata.locale` puede transportar el idioma ya resuelto dentro del Bridge. El locale es únicamente una preferencia de presentación.

**Nunca** se usa el idioma para inferir identidad, tenant, permisos, approvals o scopes.

## Seguridad

La localización no cambia la semántica de seguridad:

```text
MCP / otro protocolo
        ↓
texto ES o EN
        ↓
BridgeRuntime.invoke()
        ↓
PolicyEvaluator + approvals + replay protection + audit
```

Los mensajes localizados pueden explicar el resultado, pero el código estructurado y la decisión de policy permanecen invariantes.

## EN — Product rule

Kairoseth Agent Bridge is bilingual **Spanish + English** across surfaces visible to people, agents, and systems consuming descriptive metadata.

Localization must not duplicate the runtime or change technical identifiers.

### What is localized

ES/EN support is required for:

- tool titles and descriptions;
- discovery text exposed through MCP and future protocols;
- safe client-facing messages for approval-required, denied, and failed operations;
- future UI, installer, and Kairoseth Platform text;
- customer/operator-facing documentation where applicable.

### What is NOT localized

The following remain stable and language-independent:

- tool IDs and namespaces;
- connector IDs and instance IDs;
- protocol field names;
- error codes (`KAIROSETH_APPROVAL_REQUIRED`, etc.);
- JSON schemas and payload keys unless an external integration requires otherwise;
- correlation IDs, event IDs, nonces, and fingerprints;
- security contracts and READ / WRITE / CRITICAL decisions.

Example:

```text
generic-rest.crm.customers.get     ← stable ID
ES: Obtener cliente                ← localized title
EN: Get customer                   ← localized title
```

## Code contract

The core supports exactly these base locales:

```text
es
en
```

`ToolDefinition.localizations` can declare both texts. The Connector SDK preserves them when a tool is registered in `ToolRegistry`, allowing MCP, A2A, and future adapters to reuse one localization source.

If a translation is missing, canonical `name` / `description` is used as fallback. This keeps older connectors compatible, while official Kairoseth connectors must publish both ES and EN.

## Language selection

### MCP HTTP

`Accept-Language` can select `es` or `en` for discovery and safe result messages. Regional variants such as `es-ES`, `es-MX`, `en-US`, or `en-GB` normalize to the supported base language.

### MCP stdio / local runtime

The installation configures `defaultLocale` (`es` or `en`).

### InvocationContext

`metadata.locale` may carry the already-resolved presentation locale inside the Bridge.

Locale is presentation metadata only. It is **never** used to infer identity, tenant, permissions, approval state, or scopes.
